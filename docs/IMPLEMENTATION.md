# Architecture and milestones
M0: inspect references, legacy HTML, asset rights, and config. Scaffold Next.js App Router + TypeScript, lock dependencies, separate content from presentation. Suggested components: EnvelopeIntro, CurtainReveal, PalaceHero, InvitationDetails, WeddingTimeline, VenueSection, Closing, AudioControl. Use local assets and responsive images.
M1: intro prototype. Three.js/R3F for layered envelope geometry, flap pivot, card, wax seal; physically based paper and metallic materials, embossed normal/roughness textures, soft shadows, warm light, orthographic or restrained perspective. Create separated textures/geometry; do not use the whole envelope photo as a moving flat flap. Blender optional. GSAP timeline; pointer/touch/keyboard activation, prevent double activation, skip intro, reduced-motion fallback. Compare screenshots to approved envelope; stop for approval.
M2: curtains and palace. Prefer layered 2.5D palace art, depth/parallax, restrained camera move and subtle fountain water. Curtains can be mesh deformation or layered image animation depending on visual fidelity; no full 3D palace requirement. Avoid fake game aesthetic. No paid AI video required; propose optional video only if quality cannot be met. Stop for motion review.
M3: semantic HTML/CSS full scroll, GSAP ScrollTrigger for reveals, native scroll by default; Lenis optional only if accessible and stable. Date/time, timeline, venue photo, map link, closing. Couple photo optional, no empty broken image. Audio starts only after user gesture, visible mute control; no autoplay promise. No RSVP/menu.
M4: optimize mobile Safari/Android, desktop. Lazy-load WebGL and noncritical media, dispose textures and listeners, pause offscreen animation, cap DPR, use static fallback on context loss/low capability. Responsive AVIF/WebP where supported; preserve source originals. Aim for smooth 60fps on capable devices, measure rather than guarantee. Respect prefers-reduced-motion, keyboard focus, contrast, safe areas, dynamic viewport. Use semantic buttons and meaningful alt text.
M5: final visual approval and data verification; only then propose Vercel deployment. No production actions without explicit approval. Deliver source, lockfile, README commands, test results, screenshots and known limitations.
